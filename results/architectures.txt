=== how many architectures have this gap

Every architecture writes __syscall_cp_asm and __clone in assembly, and
unwind information for hand-written assembly only exists if somebody puts
it there. musl generates it with tools/add-cfi.$ARCH.awk - and that file
exists for two architectures.

From the musl 1.2.6 source tree:

  ARCH         syscall_cp     clone        add-cfi.awk .cfi_ in asm
  -------------------------------------------------------------------
  aarch64      syscall_cp.s   clone.s      -          0
  arm          syscall_cp.s   clone.s      -          0
  i386         syscall_cp.s   clone.s      yes        0
  loongarch64  syscall_cp.s   clone.s      -          0
  m68k         syscall_cp.s   clone.s      -          0
  microblaze   syscall_cp.s   clone.s      -          0
  mips         syscall_cp.s   clone.s      -          0
  mips64       syscall_cp.s   clone.s      -          0
  mipsn32      syscall_cp.s   clone.s      -          0
  or1k         syscall_cp.s   clone.s      -          0
  powerpc      syscall_cp.s   clone.s      -          0
  powerpc64    syscall_cp.s   clone.s      -          0
  riscv32      syscall_cp.s   clone.s      -          0
  riscv64      syscall_cp.s   clone.s      -          0
  s390x        syscall_cp.s   clone.s      -          0
  sh           syscall_cp.s   clone.s      -          0
  x32          syscall_cp.s   clone.s      -          0
  x86_64       syscall_cp.s   clone.s      yes        0

16 of the 18 architectures that have this assembly have no way to annotate it.
